# 公众号写作工作台

本机运行的写作工具：**采集素材 → 学结构 → 补公开信息 → 重写表达 → 推送公众号草稿箱**。

面向两个方向：**养老金**、**老年人感情**。设计取向是「学结构、补事实、重写表达」，
不做逐句搬运 —— 原因见文末「合规声明」。

## 快速开始

最省事的方式：**双击 `run.bat`**。它会自动挑解释器、启动服务，并在浏览器里打开
**http://127.0.0.1:8765/**；窗口不要关（关掉 = 关掉服务）。

已经有一个实例在跑时，再双击不会报端口占用，而是直接打开浏览器。

也可以手动：

```powershell
cd writer-station
.\run.ps1
```

## 目录结构

```
writer-station/
├── app.py            本地 HTTP 服务 + API（纯标准库）
├── db.py             SQLite 素材库（articles / analyses / drafts / settings）
├── collector.py      搜狗微信采集（低频 + 退避重试）
├── harvest.py        多轮采集编排：列表模式 / 补正文模式
├── analyzer.py       爆款结构分析器（规则实现，可选 jieba 分词）
├── fetcher.py        增量信息源（抓公开政策事实）
├── rewriter.py       改写引擎（标题锁定 + 结构参考 + 增量注入）
├── humanizer.py      去 AI 味：本地体检 + 多轮重写（事实锁定）
├── exporter.py       公众号 HTML 导出（全内联样式）
├── wxpush.py         公众号草稿箱推送（token/封面/draft/add）
├── seed.py           把 data/*.json 导入素材库并跑分析
├── selftest.py       端到端自测
├── run.ps1 / run.bat 启动脚本
├── web/index.html    前端界面（单文件，原生 JS，无 CDN）
├── data/             本地数据（素材库、token 缓存）★ 不入库
└── exports/          导出的 HTML ★ 不入库
```

> `data/` 与 `exports/` 已在 `.gitignore` 中排除：前者含 AppSecret、LLM Key 与采集内容，
> 后者是运行产物，都不应进版本库。

## 工作流

1. **采集** → 「素材池」页填关键词（如 `养老金,退休金上调`），选话题，先只抓列表。
2. **补正文** → 用「补正文模式」少量多次回填正文（反爬严，建议一次 ≤3 条）。
3. **分析** → 点「对已有素材做结构分析」，提炼标题模式、选题类型、正文骨架。
4. **选题分析** → 看该话题的爆款规律与可执行建议。
5. **改写** → 选素材 → 生成草稿（标题锁定，正文按骨架重写并注入公开信息）。
6. **去 AI 味** → 自己写好的稿子贴进「去 AI 味」页，体检 + 多轮重写，压掉机器痕迹。
7. **推送** → 「草稿」页点「推送草稿箱」，直连官方接口入草稿箱（**不会群发**）。

命令行也可以直接跑采集：

```powershell
python harvest.py --mode list                      # 两个话题全部关键词拉列表
python harvest.py --mode list --topic 养老金        # 只跑一个话题
python harvest.py --mode body --max 8 --delay 30   # 补正文，最多 8 条
```

## 去 AI 味（把自己写好的稿子过一遍）

「去 AI 味」页签，用于**自己写的稿子**：贴进去 → 体检 → 多轮重写 → 存成草稿 → 推送。

### 两件事分开看

| 环节 | 依赖 | 说明 |
|---|---|---|
| **体检（scan）** | 无 | 纯本地规则，不联网、不上传。8 个维度打分，逐句标风险 |
| **重写（rewrite）** | LLM | 多轮循环，每轮改完重新体检，达标即停 |

### 体检看什么

| 维度 | 权重 | 机器味越重，分越高 |
|---|---|---|
| 套话密度 | 22% | 综上所述 / 值得注意的是 / 不难发现 / 与此同时 / 在当今社会 |
| 句式均匀度 | 18% | 句长变异系数小、几乎没有短句 |
| 抽象名词 | 16% | 维度 / 赋能 / 抓手 / 闭环 / 底层逻辑 / 颗粒度 |
| 对仗排比 | 12% | 不是……而是…… / 既……又…… / 三连并列 |
| 段落均匀度 | 10% | 每段长度都差不多 |
| 具体性（反向） | 10% | 缺数字、时间、地点、引语、口语词 |
| 标点习惯 | 6% | 破折号、分号、直角引号过多 |
| 小标题规整度 | 6% | 一、二、三 + 对仗短语 + 「写在最后」 |

分数对照：`0-28 很低`、`28-45 偏低`、`45-62 中等`、`62-78 偏高`、`78+ 很高`。

> ⚠️ 这个分数是**启发式估算**，看的维度与 AI 检测器同向，但**不等于腾讯朱雀的官方判定**。
> 要真实结果，把改完的稿子粘到 [朱雀 AI 检测](https://matrix.tencent.com/ai-detect/) 再测一次。

### 重写怎么保证不跑偏

1. **事实锁定**：prompt 里把原文的数字逐个列出来，声明「一个都不能改、不能少」，且不许新增事实。
2. **多轮收敛**：`target` 默认 30 分，最多 3 轮。每轮把「上一版还剩哪些高分的维度、哪几句最像机器」喂回去继续改。
3. **改短就报警**：输出低于原文 75% 会给出警告，提醒人工补几句。
4. **越改越差就提示**：改写后分数反而更高时，直接建议用原文。

### 命令行

```powershell
python humanizer.py --file draft.txt                    # 只体检
python humanizer.py --file draft.txt --rewrite          # 体检 + 重写（需 LLM Key）
python humanizer.py --file draft.txt --rewrite --strength heavy --target 25 --out new.txt
python humanizer.py --file draft.txt --rewrite --rule   # 强制规则降级（不需要 Key）
```

### 没有 LLM Key 时会怎样

会退化成**规则降级**（删句首套话 + 拆超长句），分数只能压掉几个点，打不散句式。
必须在「设置」页填 API Key（支持任何 OpenAI 兼容接口），云端用仓库 Secret `DEEPSEEK_API_KEY`。

## 推送到公众号草稿箱

前提：**已认证**的公众号 + 后台配好 IP 白名单。

1. 「设置」页填 **AppID / AppSecret / 作者名**，保存。
2. 点 **「检测出口 IP」**，把得到的 IP 加进
   公众号后台 → 设置与开发 → 基本配置 → **IP 白名单**。
3. 点 **「测试连接」**，确认 token 能取到。
4. 「草稿」页选一篇 → **「推送草稿箱」**。

实现要点（`wxpush.py`）：

| 关注点 | 做法 |
|---|---|
| 出口 IP | **强制直连、不走代理** —— 白名单认的是真实出口 IP，走代理就对不上了 |
| access_token | 本地缓存，提前 5 分钟刷新（微信 token 是单例，频繁获取会互相顶掉） |
| 封面 | 未配 `media_id` 时自动生成暖色封面并上传为永久素材 |
| 正文 | 转全内联样式 HTML；含外链图会告警（微信只认自家域名） |
| 错误码 | `40164` / `40001` / `48001` 等做中文化提示 |

常见报错：

- `40164` 出口 IP 不在白名单 → 检测 IP 后加入，等 1~2 分钟生效
- `40001` AppSecret 不对，或已在后台被重置
- `48001` 接口未授权：账号未认证，或类型不支持草稿箱接口

## 三条硬约束（设计里已内置）

| 约束 | 说明 |
|---|---|
| **标题锁定** | 标题存在独立字段，不参与改写，模型也不被允许改动 |
| **不抄表达** | 只把「骨架 / 钩子手法」给模型，**不给原文句子** |
| **强制增量** | prompt 要求必须写进抓到的公开信息，成品要有独立信息价值 |

## 已知限制

### 1. 搜狗反爬极严（实测）

搜狗的 token 是**页级共享**的，同一页链接只能成功解析约 1~3 条，之后跳转页与搜索页都会返回验证码。

- 一次拉 8 条，实测只有前 3 条拿到正文。
- 「每条重新搜索拿新 token」也只能多撑 1 条。
- 校园网环境触发更早。

**应对**：小批量 + 大间隔（默认 20~25s），或配代理池，或做成低频定时任务慢慢攒。
因此 `harvest.py` 把「拉列表」和「补正文」拆成两阶段：列表页宽松，先把标题池铺开，
正文再分多轮回填 —— 某一轮被限流也不影响已入库的链接。

### 2. 微信公众号的 IP 白名单

本地出口 IP 若是动态的（校园网 / 家庭宽带），IP 变了就会报 `40164`，需要重新加白名单。
要长期稳定跑，建议放在固定公网 IP 的机器上。

### 3. LLM 出稿需要自己配 API

「设置」页填 OpenAI 兼容接口（DeepSeek / 通义 / Kimi / 智谱 等）即可一键出成稿；
不填则输出「写作任务书」，人工照着写。任务书模式无需任何外部依赖，开箱可用。

## 合规声明

抓取他人文章改写后发布，在著作权上属"洗稿"，与是否盈利无关；平台侧也有语义指纹比对，
头条对洗稿单次扣 40 信用分、两次封号。

本工具的设计取向是 **学结构、补事实、重写表达**，并用公开政策信息做原创增量 ——
这是降低风险的方向，但不构成法律意见。配图务必使用免费可商用图库或自制
（"图片来源于网络侵删"不能免责）。

## 技术说明

- 纯 Python 标准库（`sqlite3` / `http.server` / `urllib`），无 Web 框架依赖。
- 可选依赖：`jieba`（分词）、`Pillow`（封面渲染中文标题）；缺失时都有兜底实现。
- 前端单文件 HTML，无 CDN，离线可用。

### 双公众号账号

`wxpush.py` 支持两个账号，凭据来源按优先级解析：

1. **环境变量**（云端 Actions / 本地 `.env`）
   - 主号：`WX_APPID` / `WX_APPSECRET` / `WX_THUMB_MEDIA_ID` / `WX_AUTHOR`
   - 副号：`WX_APPID2` / `WX_APPSECRET2` / `WX_THUMB_MEDIA_ID2` / `WX_AUTHOR2`
2. **本地素材库设置**（工作台「设置」页填写，存 SQLite）

也就是说：密钥已经在 GitHub Secrets 里的，本机什么都不用填；
本机想直接跑，就在设置页填一份，不用去动 Secrets。

封面策略：账号配了 `thumb_media_id` 就复用（省永久素材配额）；
没配则**自动生成中文封面并上传**为永久素材。

> ⚠️ 微信 `access_token` 是**单例**——两处同时获取会把对方顶掉（报 `40001`）。
> 本模块做了本地缓存，请避免让云端 Actions 和本机工作台在同一分钟内都去刷 token。

### 选题看板（静态页，已上站）

`build_board.py` 从素材库聚合出一份**脱敏**数据，输出到仓库根的
`data/writing-desk.json`，由 `writing.html` 渲染：

```bash
python writer-station/build_board.py
```

**为什么脱敏**：看板页会随 GitHub Pages 公开。所以它只输出

**不含任何采集到的原文标题与正文** —— 既避开版权问题，也不暴露选题来源。

云端无素材库时用 `--keep`，可保留已有 JSON 不被覆盖：

```bash

```

### 云端无人值守（已实现）

工作流 `.github/workflows/writer-station.yml`，**每天 08:30（北京时间）**自动跑一轮；
也可以到 Actions 页面手动 `Run workflow`（可指定方向、篇数、是否推送、推哪个号、试运行）。

一轮做四件事：

```
采集素材 → 出稿（DeepSeek）→ 推公众号草稿箱 → 重建选题看板并提交
```

命令行等价物（本机也能跑，用来复现 / 调试）：

```bash
python writer-station/cloud_runner.py --dry-run                     # 只做诊断
python writer-station/cloud_runner.py --harvest --count 2 --push     # 完整一轮
python writer-station/cloud_runner.py --no-harvest --count 1 --push  # 只出稿
```

#### 三个容易踩的点（都已在配置里处理掉）

| 问题 | 处理方式 |
|---|---|
| **素材库不能进仓库** | 素材含他人标题与采集链接，而仓库是 public。素材库放 **Actions 缓存**（`run_id` 做 key + `ws-data-` 前缀滚动恢复），不落仓库 |
| **微信白名单过不去** | runner 出口 IP 每次都在变、加不了白名单。改用仓库里既有的 **SSH SOCKS5 隧道**（出口就是已加白名单的那个固定 IP），靠 `WX_PROXY=socks5h://127.0.0.1:1080` 把微信请求导过去。本机不设这个变量 → 行为与原来一致（直连） |
| **看板提交了站点却没更新** | 默认 `GITHUB_TOKEN` 推的提交**不会触发其它工作流**（GitHub 防递归），`deploy.yml` 就不跑。所以用 `GH_PAT` 推，失败了才退回 `GITHUB_TOKEN` |

#### 出稿防呆（都是被"静悄悄地坏掉"逼出来的）

- 出过稿的素材会改状态（`drafted` / `pushed`），**下一轮不再选中**，不会天天推同一篇。
- LLM 没配或调不通时产出的是「写作任务书」而不是成稿 —— 这种**默认不推送**
  （确实要推得显式加 `--allow-brief-push`）。
- 一整轮毫无产出（无新素材、无新草稿）会**返回非 0**，GitHub 会发失败邮件提醒你。
- 每轮报告同时写进 Actions 的 **Step Summary**，点开那次运行直接看，不用翻日志。

#### 如果云端采不到素材

搜狗对数据中心 IP 的封锁**可能**比家用/校园网更严 —— 这一点本机无法验证，得看第一次云端运行的结果。
所以采集设计成"尽力而为"：采不到就跳过，直接拿缓存里已有的素材出稿；只有缓存也空才会没稿可出。

判断方法：看那次运行的 Step Summary，「采集素材」一段如果带 ⚠️ 就是被拦了。
真被拦时的对策（按优先级）：

1. **不用管**。缓存会一直累积，之前采到的素材够出很久的稿。
2. 本机 `run.bat` 采一批，本机出稿推送（本机链路与云端是两套素材库，不共享，但都能出稿）。
3. 云端把采集关掉（手动触发时 `harvest=false`），只当"出稿 + 推送"用。

> ⚠️ 本机与云端共用同一套微信凭据，而 `access_token` 是**单例**：
> 两处同时刷会把对方顶掉（报 `40001`）。别让它们在同一分钟内都去取 token。
